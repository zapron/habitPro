# Email confirmation + Supabase (habitPro)

## Current product flow

Signup is password-based, but email confirmation lands on the public website:

1. User creates an account in the app.
2. The app clears password fields and shows a "Check your email" state.
3. Supabase confirmation opens `/auth/verified` on the configured HabitPro web origin.
4. The website tells the user to return to HabitPro and sign in with the same credentials.

This avoids leaving the app on the signup form with the password still visible/available in state.

## Dashboard steps

### Site URL

`Authentication -> URL Configuration -> Site URL`

Keep this as a stable fallback. Either is acceptable:

- Current app fallback: `habitpro://`
- Production website fallback: `https://habitpro-web.vercel.app`

The app passes an explicit `emailRedirectTo`, so the signup confirmation URL does not depend only on Site URL.

### Redirect URLs

Include at least:

| URL | Purpose |
|-----|---------|
| `https://habitpro-web.vercel.app/auth/verified` | Signup email verified landing page |
| `habitpro://**` | Standalone app deep links |
| `habitpro://auth/callback` | Google PKCE return / legacy email callback support |
| `habitpro://reset-password` | Password reset email (`resetPasswordForEmail`) |
| `exp://**` | Expo Go development |
| `https://auth.expo.io/@raktim24/habitPro` | Google OAuth proxy |
| `https://auth.expo.io/@raktim24/habitPro/**` | Google OAuth proxy wildcard |

When HabitPro moves from Vercel to a custom domain, add the new exact URL too, for example:

`https://yourdomain.com/auth/verified`

Then set `EXPO_PUBLIC_HABITPRO_WEB_URL` or `EXPO_PUBLIC_SITE_URL` to that new origin for future app builds.

### Email template

If using the default Supabase email template, `{{ .ConfirmationURL }}` is fine.

If using a custom template, make sure the button uses the confirmation URL generated by Supabase, not a hard-coded website link. The generated URL contains the `redirect_to` value from the app.

### SMTP

Use custom SMTP (for example Resend) so confirmation messages are delivered reliably.

## What the app sends

- `signUp` uses `emailRedirectTo = getSignupConfirmationRedirectUrl()`.
- `getSignupConfirmationRedirectUrl()` returns `{configured web origin}/auth/verified`.
- The configured web origin comes from `EXPO_PUBLIC_SITE_URL`, `EXPO_PUBLIC_HABITPRO_WEB_URL`, app config extra, or the default Vercel URL.
- Forgot password still uses the app route (`Linking.createURL("/reset-password")`) because password reset must establish a recovery session in-app.

## Password reset UX

After the user taps the reset email link, the app opens `reset-password`, establishes the recovery session from the URL, then calls `updateUser({ password })` on submit.

Supabase PKCE recovery can emit `SIGNED_IN` after `exchangeCodeForSession`. HabitPro detects recovery sessions from the access token `amr` claim in `src/lib/passwordRecovery.ts`.
